## 1. 架构基线（所有特性共同遵守）

现有数据流（`MainViewModel.cs`）是三级流水线，新代码必须按层归位：

```
读线程    OnDataReceived()      —— 只入队 / 喂解析器 / 记波形跳变（加锁），禁止任何 UI
解析线程  OnFrameEmitted()      —— 帧对象产生；只允许入队 + 加锁写曲线点
UI 线程   FlushRx()（50ms 定时）—— 批量渲染 / 统计 / 应答匹配与发送 / 引脚轮询
```

- **持久化套路**：`Config/*.json` + 私有 record DTO + `Load*/Save*` 成对方法（照抄 `LoadFrames`/`SaveFrames` 模式，MainViewModel.cs:556-607）。
- **渲染事件**：VM 不持控件引用，通过 `RxRendered`/`WaveRendered` 事件通知视图拉快照（新增曲线刷新走同一模式）。
- **测试边界**：Core 纯逻辑（匹配/求值/过滤）进 xUnit；App 层构建通过 + 手动冒烟。

## 2. 特性 A：数据统计条 + 接收过滤

### A1 目标行为

- 底部状态栏在现有 `RX/TX/帧✓✗` 基础上，增加**实测速率**（近 5 秒滑动窗口 RX 字节/s）与**连接时长**（hh:mm:ss）。
- 顶部功能条新增过滤输入框 + 启用开关：接收区只显示命中行；**`_lines` 缓冲与日志文件保持全量**，取消过滤立即恢复全量重绘。
- 过滤匹配规则：命中 = HEX 串（去空格、忽略大小写）包含 **或** 可打印 ASCII 文本包含。例如输 `AA 55` 或 `temp` 均可。

### A2 设计要点

**Core**（`src/SerialTool.Core/RxFilter.cs`，纯函数可单测）：

```csharp
public static class RxFilter
{
    /// <summary>规范化：去分隔符 + 大写（HEX 匹配用）。</summary>
    public static string NormalizeHex(string text);
    /// <summary>bytes 是否命中过滤词（HEX 串或 ASCII 文本子串）。</summary>
    public static bool IsMatch(string needle, byte[] hay);
}
```

**App/VM**（`MainViewModel`）：

- 新增 `[ObservableProperty] _rxFilterText` / `_filterEnabled` / `_rxRateText` / `_elapsedText`。
- 速率：`Queue<(DateTime t, int bytes)> _rateWindow`，`FlushRx` 投递 `_pendingRxBytes` 时入队、弹出 5 秒前样本，`sum/span` 格式化为 `B/s`/`kB/s`。**在 `FlushRx` 早退（`_rxQueue.IsEmpty`）之前执行**，保证空闲时速率也会归零、时长持续走。
- 连接时长：`TogglePort` 成功时记 `_connectedSince`，断开/出错清空；`FlushRx` 每拍刷新。
- 过滤接入两处：
  1. `FlushRx` 拼 `sb` 前过滤 `newItems`——但 `_logger.WriteLine(line)` 在过滤**前**调用，日志始终全量；
  2. `OnPropertyChanged` 中 `RxFilterText`/`FilterEnabled` 变化 → 发 `RxRenderKind.Full`（仿 `ShowHex`，MainViewModel.cs:935-937），`BuildFullText()` 内应用过滤。
- `ClearRx` 清空速率窗口（计数已有清零逻辑）。

**App/UI**（`MainWindow.xaml` 状态栏区）：

- 右侧统计 `TextBlock` 扩为 `↓nB ↑nB | 速率 | 帧✓/✗ | 时长`；过滤框放顶部功能条「接收显示组」（`清空` 按钮旁）。

### A3 验收标准

- [ ] 115200 波特率连续收数：速率显示与实际数据量同数量级（±20%），停止收数 5 秒内归零。
- [ ] 过滤开启后接收区只剩命中行；日志文件仍含全量；关闭过滤接收区恢复全量。
- [ ] 过滤词大小写/空格不敏感（`aa 55` 命中 `AA 55`）。

### A4 单元测试（`tests/RxFilterTests.cs`）

- 空/空白过滤词恒命中；HEX 子串命中（含空格容差、大小写）；ASCII 子串命中；两者都不含则不命中；过滤词奇数位 HEX 按普通文本回退匹配。

## 3. 特性 B：RTS/DTR 控制 + CTS/DSR 指示灯

### B1 目标行为

- 发送区输入框上方新增一行：RTS/DTR 两个开关（Toggle 按钮），右侧 CTS/DSR 两个圆点指示灯（绿=有效，灰=无效）。（2026-09-01 布局调整：自串口配置第三行迁入发送区，与「多帧面板」开关一字排开）
- 仅串口模式且已连接时可用；TCP 模式整行隐藏。
- 打开端口后开关状态与端口实际电平同步（防止残留上次状态）。

### B2 设计要点

**Backend**（`SerialBackend.cs`，RJCP 3.0.5 已确认暴露以下 API；CD/RI 不可用，不做）：

```csharp
public bool RtsEnabled { get; set; }   // 内部 _port.RtsEnable，端口未开时静默
public bool DtrEnabled { get; set; }
public (bool Cts, bool Dsr) Signals { get; }  // 端口未开返回 (false,false)
```

**App/VM**：

- `[ObservableProperty] _rtsOn/_dtrOn/_ctsOn/_dsrOn`；`ToggleRts`/`ToggleDtr` 两个 RelayCommand（`CanExecute = IsPortOpen && IsSerial`）。
- `TogglePort` 打开成功后：`RtsOn = _serialBackend.RtsEnabled`（同步初值）；断开/出错：四个状态复位。
- `FlushRx` 每拍（50ms）轮询 `_serialBackend.Signals` 更新 `CtsOn/DsrOn`——已在 UI 线程天然节流，无需新定时器。

**App/UI**：

- 发送区输入框上方一行（2026-09-01 迁入；TCP 模式引脚组隐藏、「多帧面板」始终可见）：`[☐RTS] [☐DTR] │ ●CTS ●DSR │ ☐多帧面板 │ ☐HEX发送 [发送]`（HEX发送/发送按钮自右侧竖列并入，输入框改全宽）；复选框统一带 Content 的应用形态（28px 基线，杜绝对齐错位），指示灯用 `Ellipse` + Style DataTrigger（绿色 `#3DA35D` / 灰 `#9AA0A6`），不新增转换器。
- 整行 `Visibility` 绑 `IsSerial`。

### B3 验收标准

- [ ] 开关 RTS：接 USB 转串口模块，用万用表/另一工具可见电平翻转；`CanExecute` 在 TCP 模式或未连接时禁用。
- [ ] 短接 USB 串口的 RTS→CTS：CTS 灯随 RTS 开关同步亮灭（≤100ms）。
- [ ] 拔线/断开后指示灯复位为灰，开关可用性正确恢复。

### B4 单元测试

Backend 引脚属性属硬件边界，不进 xUnit；覆盖方式为 B3 手动冒烟。

## 4. 特性 C：帧字段实时曲线

### C1 目标行为

- 左列底部「时序图」升级为 TabControl：「时序图 / 字段曲线」两页（原「波形」复选框控制整个底部图表区显隐，语义改为「图表」）。（2026-09-02 起图表区整体迁独立窗口，见文末日志）
- 字段曲线页：上半 ScottPlot 折线（多曲线 + 图例），下半曲线配置表格（增删改行，自动保存）。
- 每条曲线配置：启用 / 名称 / 模板名（空=任意）/ 命令HEX（可选前缀过滤）/ 数据域偏移 / 宽度(1/2/4字节) / 大端 / 有符号 / 缩放系数 / 单位。
- 仅「帧解析开启」且帧 `Ok=true` 时采样；时间轴与波形共用会话起点（秒）。

### C2 设计要点

**Core**（`src/SerialTool.Core/Framing/FieldPlot.cs`，求值纯函数可单测）：

```csharp
public sealed class FieldPlotConfig { /* A1 行为中列出的全部字段，JSON 序列化 */ }

public static class FieldPlotEvaluator
{
    /// <summary>模板/命令匹配 + 从 PayloadOffset+Offset 取 Width 字节按字节序/符号解释，
    /// 返回 v * Scale；不匹配或越界返回 null。</summary>
    public static double? Evaluate(FieldPlotConfig c, ParsedFrame f);
}
```

`ParsedFrame` 已含 `TemplateName/CommandOffset/PayloadOffset`，解析引擎零改动。

**App/VM**：

- `FieldPlotViewModel : ObservableObject`（字段全 Observable + `PropertyChanged` 触发自动保存；**配置变更时清空该曲线历史点**，避免新旧语义混画）。运行时点集 `List<PlotPt>` 由 `_plotLock` 保护，不序列化。
- `ObservableCollection<FieldPlotViewModel> FieldPlots` + `Config/field_plots.json` 持久化（DTO 模式同 `FrameDto`）。
- 采样：`OnFrameEmitted`（解析线程）中 `f.Ok` 时逐条 `Evaluate`，命中加锁入点集；上限 20k 点/条，超出裁掉最旧一半（仿 `MaxWavePoints`）。
- 刷新：`FlushRx` 末尾 `WaveRendered` 事件已存在——视图端在曲线页可见时额外拉 `FieldPlotSnapshot()`（锁内拷贝 `(name, unit, xs, ys)[]`）。
- `ClearRx` 清空全部曲线点集。

**App/UI**：

- TabControl 替换现有 GroupBox；曲线页 `WpfPlot`（高度 180）+ `DataGrid`（高度 ~110，列见 C1）；空态提示「需开启帧解析」。
- ScottPlot 渲染仿 `OnWaveRendered`：移除旧 Scatter → 逐条 `Add.Scatter` → 跟随模式 `SetLimitsX` 最近 60 秒 → `Refresh()`。

### C3 验收标准

- [ ] 用 scripts/feed_frames.py 或回环发送示例模板帧，字段值变化实时成曲线；图例含名称+单位。
- [ ] 修改偏移/宽度等配置后旧点清空、新点按新配置入图；重启程序配置保留。
- [ ] 20k 点上限裁剪生效（长时间回环无内存暴涨、无渲染卡顿）。
- [ ] 帧解析关闭时曲线页空态提示，不报错。

### C4 单元测试（`tests/FieldPlotTests.cs`）

- 大小端 1/2/4 字节取值正确；有符号解释（0xFFFF → -1）；模板名不匹配返回 null；命令前缀不匹配返回 null；Offset+Width 越界返回 null；Scale 换算。

## 5. 特性 D：自动应答器

### D1 目标行为

- 右列「多帧发送」升级为 TabControl：「多帧发送 / 自动应答」。
- 规则 = 模板（空=任意）+ 命令HEX 前缀（可选）+ 匹配HEX 子串（可选，与命令为"与"关系）→ 回复HEX + 延迟ms + 仅一次 + 命中计数。
- 仅 `Frame.Ok` 的接收帧参与匹配；命中后按延迟到期回发（50ms 调度粒度），回显行用 `⇄` 与手动发送 `→` 区分。
- 「仅一次」命中后规则自动禁用并持久化（握手类指令防重复应答）。

### D2 设计要点

**Core**（`src/SerialTool.Core/Framing/AutoReply.cs`，匹配器纯函数可单测）：

```csharp
public sealed class AutoReplyRule { /* D1 字段 + HitCount */ }

public static class AutoReplyMatcher
{
    /// <summary>返回第一条启用且匹配的规则（Once 语义由调用方处理）；HEX 非法的规则视为不匹配。</summary>
    public static AutoReplyRule? Match(IEnumerable<AutoReplyRule> rules, ParsedFrame f);
}
```

匹配语义：`TemplateName` 空=任意模板，否则相等；`CommandHex` 非空 → `Raw[CommandOffset..]` 前缀相等；`MatchHex` 非空 → `Raw` 含该子串；两者同时配置取"与"。

**App/VM**：

- `AutoReplyViewModel : ObservableObject`（Observable 字段 + `HitCount` UI 显示，命中计数**不触发保存**）；集合持久化 `Config/auto_reply.json`。
- 调度：`FlushRx` 处理 `newItems` 时对 `Frame is { Ok: true }` 跑 `Match`，命中 → `HitCount++`、`Once` 则禁用并保存、`Hex.TryParse(ReplyHex)` 成功则 `(due, bytes, label)` 压入 `_pendingReplies`。
- 发送：`FlushRx` **每拍先于渲染**处理到期应答（早退前执行，队列非空也可能无新收数）→ `WriteBytes(bytes, silent:true, tag:"⇄")`。
- `RxItem` 增加可选 `Tag` 参数，`FormatLine` 显示 `Tag ?? (IsTx ? "→" : "←")`。
- 延迟精度 = `FlushIntervalMs`（50ms），满足串口应答场景；文档/UI 提示注明。

**App/UI**：

- 右列 TabControl；应答页 DataGrid 列：启用/名称/模板/命令HEX/匹配HEX/回复HEX/延迟ms/仅一次/命中(只读)，底部 添加/删除选中/清空 按钮（复用多帧面板样式）。

### D3 验收标准

- [ ] 回环（TXD→RXD 短接）发送匹配帧：50ms+DelayMs 内收到回复且回显行前缀 `⇄`；命中计数 +1。
- [ ] 命令HEX 不匹配的帧不应答；`Once` 规则命中一次后自动取消勾选，重启仍为禁用。
- [ ] 规则 HEX 非法（奇数位）时状态栏提示且不崩溃。
- [ ] 未开启帧解析时应答页给出空态提示（应答依赖帧匹配）。

### D4 单元测试（`tests/AutoReplyTests.cs`)

- 模板/命令/子串三种条件单独与组合匹配；`Once`+禁用规则不匹配；非法 HEX 规则跳过；首条匹配优先。

## 7. 风险与边界

| 风险 | 对策 |
| --- | --- |
| 解析线程写曲线点与 UI 拉快照竞争 | 全部经 `_plotLock`；快照在锁内拷贝数组 |
| 高波特率下应答/过滤/统计都在 `FlushRx` 串行执行造成 UI 卡顿 | 三者都是 O(新行数) 轻逻辑；若将来超预算，再拆独立定时器 |
| RJCP 无 CD/RI 引脚 | 只做 CTS/DSR 两灯，UI 预留行宽 |
| 接收框 TextBox 不支持局部高亮 | 本批次不做高亮（过滤先行）；AvalonEdit 替换列为后续独立事项 |
| ScottPlot 中文图例豆腐块（已知问题） | 曲线图例沿用曲线名（建议用户用英文/数字命名），单位进 WPF 提示行 |

## 8. 本批次明确不做（后续候选）

- 回复帧变量占位符 `$(seq8)`/`$(crc16)`（变量化发送，三处发送入口共用）。
- AvalonEdit 接收区高亮；Modbus RTU 主/从；XMODEM/YMODEM；多端口标签（V1.3 原计划）。
